# Beles платформасы: пайдалану нұсқаулығы

## Орта айнымалылары (Vercel → Settings → Environment Variables)

| Айнымалы | Не үшін |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase жобасы (браузерге көрінеді, RLS қорғайды) |
| `SUPABASE_SERVICE_ROLE_KEY` | Тек серверде. Ешқашан браузерге не GitHub-қа шықпасын |
| `ADMIN_PASSWORD` | Иесінің әкімші құпия сөзі. Ауыстырса – барлық әкімші сессиялары жабылады |
| `SESSION_SECRET` | Cookie қолтаңбасының кілті (32+ кездейсоқ таңба). **Міндетті түрде орнатыңыз.** Алғаш қосқанда барлық мұғалім мен оқушы бір рет қайта кіреді |

## Әкімшілер

- **Иесі**: `/admin/login` – логинді бос қалдырып, `ADMIN_PASSWORD` енгізеді.
- **Әкімші-мұғалім**: иесі «Мұғалімдер» бетінде «Әкімші» белгісін қояды. Сол адам өз логині мен құпия сөзімен кіреді, журналда аты көрінеді. Белгіні алса – қолжетімділік бірден жабылады.
- **Журнал** (`/admin?view=journal`): кім, қашан, не өзгертті; қате кірулер; сайттағы қателер.

## Қорғаныс

- Бір IP-ден 15 минутта 40 қате кіру (PIN не құпия сөз) → 15 минут бұғат (орталықтың ортақ Wi-Fi-ы ескерілген). Бір аккаунтқа 5 қате → 15 минут.
- Оқушының PIN-і 5 рет қате терілсе → 10 минут бұғат.
- Ашық кіру тізімдерінде оқушының тегі қысқартылады: «Айтбек А.».
- Speaking жазбалары жабық `speaking` қоймасында, мұғалімге 2 сағаттық сілтемемен ашылады.
  Ескілерін көшіру: `node scripts/move-speaking.mjs` (тізім), сосын `--apply`.
- Мұғалім құпия сөздері PBKDF2-мен сақталады, ескілері кірген сәтте автоматты жаңарады.
- Тест таймері серверде тексеріледі: уақыт біткен соң жауап қабылданбайды, бөлім өзі жабылады.

## Базаның өзгерістері (миграциялар)

Жаңа өзгерістер тек `supabase/migrations/` ішіндегі файлдар арқылы, атауы күнмен: `20261026_01_security.sql`.
Әр файл қайта іске қосуға қауіпсіз болуы керек (`if not exists`).

- **Автоматты**: GitHub → Settings → Secrets → `DATABASE_URL` қосылса, main-ге түскен жаңа миграциялар өзі қолданылады.
- **Қолмен**: `DATABASE_URL=... npm run migrate` немесе файлды Supabase SQL Editor-ға қойып іске қосу.
- Күйін көру: `npm run migrate:status`.

`supabase/*.sql` (түбіріндегі) – бұрынғы файлдар, тарих үшін қалды.

## Тексеру және жариялау

1. Өзгерістер алдымен бөлек тармаққа (`ielts`) жіберіледі → Vercel preview сілтемесі.
2. GitHub Actions **CI**: типтер, unit тесттер (`npm test`), толық build.
3. CI жасыл және preview дұрыс болса ғана → `main` → production.

Ұсыныс: GitHub → Settings → Branches → `main` үшін «Require status checks to pass» (CI) қосу.

## Сақтық көшірме

Supabase Free жоспарында автоматты күнделікті көшірме жоқ. Аптасына кемінде бір рет:

```bash
DATABASE_URL="postgres://..." npm run backup     # backups/beles-<күн>.dump
```

Файлдарда балалардың деректері бар – оларды GitHub-қа, ашық бұлтқа салмаңыз (`backups/` git-тен тыс).

Айына бір рет **қалпына келтіріп тексеріңіз** (бос тест базаға):

```bash
pg_restore --no-owner -d "$TEST_DATABASE_URL" backups/<файл>.dump
```

Supabase Pro жоспарына өтсе – күнделікті автоматты көшірме және PITR қосылады.

## Журналды тазалау

Supabase SQL Editor: `select prune_logs();` – 180 күннен ескі әрекеттерді, 90 күннен ескі қателерді өшіреді.
