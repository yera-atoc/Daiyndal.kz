# Beles

Платформа для подготовки к НИШ(НЗМ), БІЛ, РФМШ, ЕНТ(ҰБТ) (5–6 класс),
несколько предметов. Next.js 14 (App Router) + TypeScript + Tailwind CSS +
Supabase.

## Что готово

- `/` — лендинг: hero, 6 предметов, 4 программы (НИШ(НЗМ) / БІЛ / РФМШ /
  ЕНТ(ҰБТ)), CTA
- `/tests` — банк тестов с фильтром по предмету (пока моковые данные в
  `lib/tests.ts` — не связаны с Supabase)
- `/admin` — закрытая панель администратора (за паролем):
  - **Оқытушылар** — добавление/удаление учителей
  - **Оқушылар** — добавление/удаление учеников, привязка к учителю
  - **Қатысу** — отметка посещаемости по дате: «Келді» / «Келмеді» на
    каждого ученика, счётчик пришедших

Данные учителей, учеников и посещаемости хранятся в вашей базе Supabase —
видны с любого устройства.

## Настройка

### 1. Переменные окружения

Скопируйте `.env.example` в `.env.local` и заполните:

```
SUPABASE_URL=https://xxxxx.supabase.co
SUPABASE_SERVICE_ROLE_KEY=...
ADMIN_PASSWORD=...
```

- `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` — из вашего проекта Supabase:
  Project Settings → API. **Service role key** — секретный, не публикуйте
  его и не добавляйте в код с префиксом `NEXT_PUBLIC_`.
- `ADMIN_PASSWORD` — пароль для входа на `/admin`. Хранится только на
  сервере; в браузере остаётся лишь хеш в защищённой httpOnly-куке.

На Vercel эти же переменные нужно добавить в Project → Settings →
Environment Variables.

### 2. Таблицы в Supabase

Откройте в Supabase: SQL Editor → New query, вставьте и выполните содержимое
файла `supabase/schema.sql` (создаёт таблицы `teachers`, `students`,
`attendance`). RLS включён без публичных политик — таблицы недоступны
напрямую из браузера, все запросы идут через серверные API-роуты этого
проекта с сервисным ключом.

### 3. Запуск локально

```
npm install
npm run dev
```

Открыть <http://localhost:3000>, панель — <http://localhost:3000/admin>.

## Публикация на GitHub

```
git init
git add .
git commit -m "Beles: лендинг + тест-банк + админ-панель"
git branch -M main
git remote add origin https://github.com/<ваш-логин>/<название-репозитория>.git

```

Если пушите в уже существующий репозиторий — просто `git add .`,
`git commit`, `git push` без `git init`.

**Важно:** `.env.local` не попадёт в git (он в `.gitignore`) — переменные
окружения задаются отдельно на Vercel.

## Деплой на Vercel

1. New Project → выбрать репозиторий
2. Добавить переменные окружения (см. выше) в Settings → Environment
   Variables
3. Deploy

## О безопасности админ-панели (как сейчас устроено)

Вход — по одному общему паролю (`ADMIN_PASSWORD`), без отдельных логинов на
каждого администратора. Это быстро настроить, но подходит для одного
человека или небольшой доверенной команды, не для публичного доступа
многих людей. Если понадобятся отдельные учётные записи — можно позже
перейти на Supabase Auth (email/password или magic link для каждого
администратора).
